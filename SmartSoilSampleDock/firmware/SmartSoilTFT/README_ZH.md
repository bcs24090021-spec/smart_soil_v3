# ST7789 彩屏版本

按照用户确认的 ST7789、240×320 面板编写。开机横屏显示稻作照片与 Smart Soil 封面，按 Start 才进入现场传感器数据页；按 Next 进入基于当前读数的前三候选摘要，再查看作物照片与初筛理由。pH 显示为未复核的原型估算值；不初始化旧 OLED。

## 八针屏幕接线

断开 USB，拆下旧 OLED，再按照屏幕印字连接。适用于经典 ESP32 Dev，不适用于未经核对的 C3/S3 板型。

| 屏幕 | ESP32 |
| --- | --- |
| GND | GND |
| VCC | 3V3（依据用户确认的 3.3–5V 供电规格） |
| SCL | GPIO18，SPI SCK |
| SDA | GPIO23，SPI MOSI |
| CS | GPIO25 |
| DC | GPIO26 |
| RST | GPIO33 |
| BL | 先确认本模块的背光规格，见下文 |

SDA/SCL 是这块屏的 SPI 命名，不是 I2C；不要沿用 OLED 的 GPIO21/22。没有 MISO，不需要连接 GPIO19。

BL 暂未从这块通用模块的规格书核实。本代码不驱动 BL：如果厂家确认它是可直接接 3.3V 的背光输入，可接 3V3 常亮；如果是裸 LED 电源输入，需要按厂家要求限流或使用背光驱动。不要直接用 ESP32 GPIO 给未知背光负载供电。Adafruit 模块的 BL 电路不保证与你的八针模块相同。

三个传感器接线不变：DS18B20 DATA 接 GPIO4，4.7kΩ 上拉至 3V3；DHT22 DATA 接 GPIO27，保留模块已有上拉；土壤 AOUT 接 GPIO35。三个模块供电使用各自确认支持的 3V3，所有 GND 共地。

两个按钮使用内部上拉：Start 一脚接 GPIO13、另一脚接 GND；Next 一脚接 GPIO14、另一脚接 GND。断电后再接线，按钮不要接 5V。未装按钮时，也可在 115200 串口发送 `s` 开始新样本、`n` 翻看下一页。开机停在封面，Next 在封面不起作用；Start 清除旧画面和读数计数，立即安排新读取。读数有效后，Next 的流程是测量页 → MEASURED TOP 3 摘要 → 候选 1 → 候选 2 → 候选 3 → 测量页。按 Next 时冻结一份读数快照；浏览结果期间传感器仍每约 3 秒读取并输出 JSON，返回测量页会显示最新实时读数。

## pH 电压诊断

PH4502C 用其要求的 5V 电源供电，GND 与 ESP32 共地。PO 经两个 10kΩ 电阻分压：PO → 10kΩ → 中间节点 → 10kΩ → GND；中间节点接 GPIO34，PO 禁止直接接 ESP32。先断开 ADC，核实输出最大范围并用万用表检查分压，再断电接 GPIO34。这套分压以前端最大输出不超过 5V 为前提，不是通用过压保护。

本次用户报告 PO 约 4.6V、中间节点约 2.2V，只代表当时测量，不证明 pH 已正常或所有状态下安全。未校准时屏幕只显示 pH ADC 毫伏值，串口输出 ph_adc_mv 和 ph_adc_spread_mv。与校准程序相同，读取 41 次后去掉两端各 5 次；全组跨度大于 35mV 标为 unstable；近 ADC 饱和或平均值超出约 50–3150mV 标为 adc_out_of_range。检查仅针对读数，不能防止硬件过压，也不能识别浮空输入。

原型 pH 流程：现在可直接上传本主程序，不需要重新购买 pH 4 缓冲液。固件优先读取 ESP32 `smartsoilph` 中已保存的 `cal4` / `cal918`；缺少任一点时，回退到本次实测记录的 pH 4.00 = 2226.7 mV、pH 9.18 ≈ 1944.0 mV。旧的 `cal7` 数据不会使用。开机 30 秒后，ADC 电压有效且单次采样跨度不超过 300 mV 时，最近 5 次电压的中位数会换算成带 `~` / `est` 的 pH 估算数字并参与原型初筛；跨度大于 35 mV 时 JSON 标记 `noisy_estimate`。跨度超过 300 mV、量程异常或换算超出 pH 0–14 时不显示数字，也不参与初筛；屏幕显示 `CHECKING`，JSON 的 `ph` 为 null。JSON 的 `ph_calibration` 说明是否用了记录值。300 mV 是演示用显示门槛，不代表测量准确度。此前 pH 7.00 缓冲液复核结果波动且与两点推算不一致；本原型 pH 数字不能宣称已验证准确度或用于实际农业决策。这里没有 pH 温度补偿，校准和测量应尽量在相近温度进行。如以后拿到新鲜缓冲液，可用 `../PH4502CTest/PH4502CTest.ino` 重新测两点，保存后本主程序会优先读取新值。

E201-C 是液体 pH 探头。测土壤时，应按一致的土水比例制备土壤悬液，等待稳定后测悬液；不要直接插进干土。若在同一个土槽里加水，之后的湿润指数反映加水后的样本，不能当作原土湿度。要同时呈现原土湿润度与 pH，请先记录未加水的原土湿润度，再另取一份土制备悬液测 pH；当前固件不会自动把两个时刻的结果合并为同一测量。

## Arduino 上传

打开本文件夹的 SmartSoilTFT.ino，选择 ESP32 Dev Module 与实际 USB 端口。所需库：Adafruit ST7735 and ST7789 Library、Adafruit GFX Library、Adafruit BusIO、OneWire、DallasTemperature、DHT sensor library、Adafruit Unified Sensor。SPI 来自 ESP32 开发板包，不另外安装。

代码已在本机 Arduino ESP32 环境编译，并以 115200 baud 上传到 `/dev/cu.usbserial-10`；上传哈希校验和重启后串口读数均通过。尚未通过实物目视验证彩屏画面。串口 115200 约每 3 秒输出一次 JSON。SPI 没有确认设备响应的读回机制，串口初始化文字不代表屏幕已经正常显示。打开本目录的 `SmartSoilTFT.ino` 时，要保留相邻的 `../SmartSoilCropPhotoPreview/CropPhotoAssets.h`，因为照片素材由那里引用。

土壤保留原始 ADC 和毫伏，并显示 0–100 的相对湿润指数。暂用用户实测的干土 2646、加水后样本 1756；常量在 WetnessReference.h。公式为 (2646 - raw) / (2646 - 1756) × 100，显示限幅到 0–100。它只是两份样本之间的演示刻度，不是实际含水率，也不是浇水建议。

读数超出样本参考范围时，指数旁显示 *，串口 soil_status 为 demo_outside_sample_references；不能把限幅后的 100 当成饱和土壤。ADC 异常时指数显示 ERR、串口 soil_wetness_index 为 null。soil_moisture_pct 仍保持 null。模拟脚浮空也可能产生读数，本代码无法独立确认连接。

测量页底部明确标注 INDEX NOT VWC。更改供电、探头、接线、土壤或插入方式后，必须重新检查参考值。RANGE! 表示近 ADC 饱和或超出保守量程，不是过压保护。数字传感器失败显示 ERR；pH 未校准或读数不合格时只显示 ADC 电压。

前三候选使用现场快照，不使用随机或预设的传感器数据；但作物匹配规则仍是未验证的初筛，不是实地种植建议。仅在土温与土壤 ADC 都有效、且湿润指数未超出两份样本参考范围时生成前三候选。温度落在 Word 的暂用范围内得 2 分；湿润指数按 `<30`、`30–<70`、`>=70` 分为 Dry、Moderate、Wet，作物按 Word VWC 范围中点 `<=30`、`>30–44`、`>44` 归入三个暂用类别；类别相同得 2 分，相邻得 1 分，否则 0 分。pH 校准且读数有效时，若处于 Word 作物暂用 pH 范围再得 2 分，满分为 6；否则不计 pH，满分为 4。相同分数按原始表格顺序列出，不证明前三名农艺优先级。空气湿度是真实环境读数，但不参与排名。`soil_moisture_pct` 始终为 null，因为目前没有经土壤类型校准的体积含水率。

屏幕不亮先核对背光、电源与接线；亮但无画面核对 CS/DC/RST 和驱动；画面错位核对实际分辨率及偏移，颜色不对再核对颜色顺序/反相配置。不要为了试屏而把 ESP32 信号改成 5V。
